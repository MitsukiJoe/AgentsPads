## 技术实现与约束边界


| 模块               | 当前技术实现                                                                                                                                                                                                     | 约束与安全边界                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **系统架构**         | 手机端基于 Android Flutter；桌面端基于纯 Rust 构建，原生支持 Windows 与 macOS                                                                                                                                                  | 坚决不使用 Electron、Python 运行时或 Flutter 桌面壳，保证极低资源占用；桌面配对窗只在网卡、权限、配对码、更新状态变化或用户操作时重绘，静止时不持续出帧                                                                                                                                     |
| **Android 原生桥接** | 极简原生 Kotlin 模块：仅当目标位于物理 Wi-Fi 同网段时绑定该网络，并负责 OkHttp WebSocket 通信、匿名录音活动状态监听、输入法 subtype 读取，以及输入框为空时把输入法退格转成电脑 Backspace                                                                                                                          | UI 界面、响应式状态与手势交互全部留在 Flutter 层；绝不录制任何音频，不申请麦克风权限                                                                                                                                    |
| **连接与通信协议**      | 手机端通过本地局域网明文 WebSocket 连接电脑端 TCP `9618`；通信采用固定格式的 JSON 数据包。每次连接电脑端先发随机挑战，手机须用配对密钥的 HMAC-SHA256 应答（首次手动配对时改为提交 4 位配对码），10 秒内未通过即断开                                                                                                                                                 | 无云端中继、无用户账号、无外网依赖；**鉴权只防未授权设备连接，不加密传输内容：同一网络中能抓包的人可以看到你发送的文字，能劫持流量的人可以篡改输入。不建议在不可信网络（公共 Wi-Fi、共享办公网等）使用，切勿将端口映射暴露至公网**                                                                                                                              |
| **桌面端网络监听**      | 服务端监听 `0.0.0.0:9618`，不绑定单一物理网卡                                                                                                                                                                              | 实体有线、Wi-Fi 与 Wi-Fi 热点等共享网络地址在可单播到达且本机防火墙放行 TCP 9618 时可连接                                                                                                                                           |
| **配对机制**         | 桌面端呈现依据系统 DPI 缩放（约 260pt）的高清二维码，并同步提供可一键复制的 `IP:端口`；二维码右侧的网卡列表支持切换当前活跃的实体、隧道与虚拟组网网卡 IPv4。二维码携带配对密钥；手动输入地址时需填配对窗显示的 4 位一次性配对码（窗口隐藏即失效，用过即换新，累计输错 5 次锁定），通过后电脑下发配对密钥 | 未启用或没有候选 IPv4 的网卡会被过滤；常见且能明确识别为仅供本机使用的容器/虚拟机接口也会被排除；扫码非唯一通道，手机端也支持手动输入并持久化候选 IP 地址池。手动配对时配对码与下发的密钥均为明文传输，配对当下若被旁听仍可能泄露；配对窗「设置」页「重置配对密钥」可作废全部已配对手机                                                                                                        |
| **多设备管理**        | 每台电脑对应一条独立的 WebSocket 长连接，各自维护重连逻辑；手机端统一向勾选为激活的在线目标发射数据；设备目标条默认在输入框下方，设置中可改到顶栏「已连接」旁                                                                                                                                                    | 任意一个已勾选的目标机器发送成功即立即清空手机端本地输入框，不强制阻塞等待每台机器的回执 ACK；手机应用不可见时断开连接并停止重连，恢复可见时自动连接                                                                                                                                    |
| **文字注入流程**       | 文字先在手机端输入法完成完整组字；电脑端接收后写入纯文本剪贴板，随即注入真实的 `Ctrl+V` / `Cmd+V`。当且仅当开启「自动回车」且粘贴成功时，系统会精准等待 80ms 留给焦点应用消化文本，随后发出 Enter                                                                                           | 电脑端接收到的是正规粘贴系统快捷键，而非模拟键盘敲击字符 `v`；安全保护输入框或禁用粘贴的程序可能拒绝接收。普通文字发送与手动 Enter 键不受该 80ms 影响                                                                                                 |
| **语音判定逻辑**       | 输入框获得焦点后，必须检测到底层 Android 录音活动，或输入法 subtype 明确标识为 `voice`；同时要求光标处于文末、无选区且已退出 composing 组字态                                                                                                                  | 基于底层来源证据而非字形猜测，避免由手打和粘贴本身单独触发，无需维护输入法白名单即可适配标准语音输入法。稳定延迟支持 0 / 0.5s / 1s / 1.5s（默认 0.5s），充分留出 AI 语音整理排版时间。录音状态检测需 Android 7+；Android 5/6 依赖 `voice` subtype。因系统匿名化机制，并发的无关录音是剩余理论边界 |
| **快捷键注入**        | 手机端发送 key + modifiers；Windows 端调用底层 `SendInput`，macOS 端调用 `CGEvent` 注入真实的 keydown / keyup 事件。输入框聚焦且为空时，软键盘或按键退格同样按此路径注入 `Backspace`，不占用快捷键条；输入框为空时发送键切换为回车图标，点击即按此路径注入 `Enter`                                                                                                               | 全局统一维护一套自定义快捷键配置，不针对特定 Agent 软件分别维护配置档。空框退格只在输入焦点仍在手机输入框且本地文本为空时转发；框内仍有文字时只编辑手机本地内容。空框回车与退格共用同一空框判定，框内一有文字发送键即恢复为发送文字                                                                                                                                              |
| **撤回机制**         | 手机端指示勾选的电脑在 Windows 注入 `Ctrl+Z`、在 macOS 注入 `Cmd+Z`，并将上次发送的内容恢复回手机输入框内                                                                                                                                      | 撤回是否生效取决于当前焦点软件自身的 Undo 历史记录；终端及 CLI 命令行可能忽略或另行解释该快捷键，已执行的指令与终端输出无法撤回                                                                                                               |
| **光标与指针控制**      | 手机端传输相对位移、按键位图与滚轮逻辑像素增量；发送频率使用 60/120/240/320/480/560/960Hz 七档滑块，默认取屏幕**支持的峰值刷新率 ×2** 后不超过该值的最高档（120Hz → 240Hz，230Hz → 320Hz，获取失败默认 60Hz），保留手动选择；Android 窗口主动申请峰值刷新率以防止动画锁帧；按 Windows / macOS 独立调节指针速度（均为 ×1–×7，Windows 默认 ×6，macOS 默认 ×3）与滚轮速度（Windows ×1–×7，默认 ×1；macOS ×4–×28，每档 ×4，默认 ×16），各平台可独立反转滚动方向，Mac 默认开启；电脑端通过 `SendInput` / `CGEvent` 注入；macOS 连点写入系统 click count（约 500ms、约 5pt 内，最多三击；拖拽打断连点） | 绝不做虚假路径插值。当多段真实位移挤在同一次屏幕刷新渲染时，光标可能视觉上显得「瞬移」——那是系统一次性呈现滞后位移，而非定位错误；往返位移绝对跟手且零累计漂移。触控板/轨迹球/小红点共享调速与左右滚轮配置；非物理 HID 硬件，不做电竞级或跨多显示器绝对坐标映射                                                |
| **本地数据持久化**      | Android 端基于 `SharedPreferences` 存储设备列表、激活状态、快捷键、主题、语音延迟、输入框高度、指针模式/尺寸/调速/频率、滚轮速度/左右位置/方向反转、设备条位置、横屏布局、强制横屏及长按轻震                                                                                                                     | 绝无任何远程账号同步，所有配置与历史数据 100% 留存在本地设备中                                                                                                                                                  |
| **系统权限要求**       | Android 端需要网络访问与扫码所需的相机权限，语音状态检测无需麦克风权限；macOS 端必须在「系统设置 - 隐私与安全性」中授予「辅助功能」权限以注入按键与指针                                                                                                                       | macOS 辅助功能 TCC 与代码签名是彼此独立的机制；Windows 防火墙需允许局域网内的 TCP 9618 通信                                                                                                                       |
| **桌面开机启动**       | 桌面配对窗「设置」页提供默认关闭的「开机启动」开关；Windows 在 Startup 目录创建或移除启动项，macOS 打包 App 在 `~/Library/LaunchAgents/` 创建或移除 LaunchAgent                                                         | 仅在用户主动开启后写入本地登录项，不联网、不提升权限；关闭开关会移除对应启动项                                                                                                                                           |
| **Windows 管理员模式**  | 「设置」页「以管理员模式启动」默认关闭；开启时授权一次 UAC，注册一个以最高权限运行的计划任务，之后手动启动都经该任务静默以管理员身份重启，开机自启由另一个带登录触发的任务直接以管理员身份启动 | 仅 Windows；只在用户主动开启并通过 UAC 授权后生效，用于向任务管理器等管理员权限窗口注入输入；关闭后下次启动恢复普通权限；管理员实例的配对密钥与普通实例分开，存于仅 Administrators/SYSTEM 可访问的目录，普通进程读不到，切换模式后手机需重新扫码；若计划任务失效（如 EXE 被移动），以普通权限运行并自动关闭开关，可重新开启注册；管理员实例的主题、引导记录与诊断日志在 `%ProgramFiles%\AgentsPads\state`（继承程序目录权限，普通用户可读）；管理员模式下「开机启动」是另一个带登录触发（延迟约 30 秒）的最高权限计划任务，由管理员实例用 `schtasks /Change` 启停，不写用户目录；开启管理员模式时清除用户 Startup 里的旧启动项，关闭后回到开启之前的普通设置；是否以管理员模式启动由该程序目录里的标记决定 |

## 运行日志位置

诊断日志默认关闭，且只对本次运行有效。遇到异常或连接问题时，在配对窗「设置」页打开「诊断日志」（开启时会清空旧日志），复现问题后点「打开目录」，或通过系统托盘菜单「打开日志」查看；「清空」可随时删除已有日志。重启 AgentsPads 后日志自动关闭。日志位置：

- **Windows**：`%APPDATA%\AgentsPads\logs\`；管理员模式为 `%ProgramFiles%\AgentsPads\state\logs\`
- **macOS**：`~/Library/Logs/AgentsPads/`

## 自动检查与确认更新机制

AgentsPads 内置轻量的跨平台更新通道。每个正式 Release 都附带版本、下载地址与 SHA-256 的更新清单；客户端优先读取 GitHub Release 资产，失败时自动切换到两个 CDN 镜像，不依赖 GitHub REST API 配额。三端保持同一套检查节奏，下载与安装始终由用户确认，不会在后台擅自更新：

- **自动检查频率**：
  - 桌面端和 Android 端每次启动后都会在后台检查一次；
  - 应用持续运行时，从启动开始每满 24 小时再次在后台检查；若中途重启，则新进程启动后重新检查一次；
  - 检测过程由应用内 HTTPS 客户端完成，主源不可用时按顺序切换 CDN 镜像，不会启动 CMD、终端或自动下载安装；
  - 后台自动检查与自动提示不会主动弹窗：桌面端只在发现新版时于窗口顶栏版本号旁显示可点击的更新入口，检查状态放在「关于」页；Android 端发现新版时只在首页底部版本号旁亮起绿点与「可更新」，用户点击后才弹出确认窗口。手动「检查更新」才显示检查中、已是最新或失败结果。
- **版本状态直观呈现**：
  - 桌面端配对窗口顶栏（监听端口旁）常驻显示当前版本号；「关于」页显示最近一次检查结果，并可手动「检查更新」；
  - 检测到新版本后，顶栏版本号旁与「关于」页会显示「**更新到 vX.Y.Z**」按钮；只有用户点击后才开始下载和替换。
- **Windows（应用内下载与自替换）**：
  - 用户点击「更新到 vX.Y.Z」后，程序通过应用内 HTTPS 在后台下载新的 `agentspads-windows-x64.exe`，并在界面显示进度；整个过程不调用 CMD、更新脚本或系统 `curl`；
  - 下载完成后先按清单校验 SHA-256；校验通过才把运行中的旧 EXE 改名为 `.old`、让新 EXE 落位并启动。校验或替换失败会保留旧版本并在界面显示原因；
  - 新版本启动时会清理 `.old` / `.new` 更新残留；对于旧版本遗留的 `agentpad_updater.bat`，只有内容特征匹配 AgentPad 旧更新器时才会删除，避免误删用户文件。
- **macOS（App Bundle 自动换位）**：
  - 用户点击「更新到 vX.Y.Z」后，程序在后台下载 `agentspads-macos-arm64.zip`，按清单校验 SHA-256 后再解压；
  - 只要当前程序从 `.app` Bundle 内运行，无论 App 放在「应用程序」还是其他可写目录，都会先将旧 Bundle 改名让位，再把新 Bundle 放回原路径，并通过 `open -n` 启动新版本；
  - 若 Bundle 无法直接改名换位，会尝试通过系统 `ditto` 原地覆盖；只有并非从 `.app` 内运行的开发构建才会打开解压目录供手动处理，无需挂载 DMG。
- **Android（系统安装器确认）**：
  - 首页底部常驻显示当前版本号，遵循启动后及每满 24 小时一次的后台自动检查；
  - 自动检查发现新版时仅在版本号旁亮起绿点与「可更新」，不弹窗打扰；点击后弹出更新日志，再点击「下载并更新」才会下载最新 `agentspads.apk` 并唤起系统安装器。应用包名是 `app.agentspads`；同一包名且签名相同的覆盖安装会保留已保存的设备和偏好。此前包名为 `app.agentpad` 的安装不会被这次改名覆盖，需要单独安装新包，旧应用里的数据不会带过来。

## 项目工程结构

```text
AgentsPads/
├── desktop/                 # 桌面端（Rust 原生核心：Windows / macOS）
│   └── crates/
│       ├── agentpad/        # 系统托盘、配对展示窗、WebSocket 服务端
│       └── agentpad-input/  # 纯文本注入、系统按键与光标指针驱动
├── android/                 # 移动端（Android 手机端应用）
│   ├── lib/                 # Flutter 界面渲染、状态管理、手势识别、协议客户端
│   └── android/app/src/main/kotlin/
│       └── app/agentspads/  # 物理 Wi-Fi 绑定、WebSocket 客户端、语音证据原生桥接、空框退格
├── docs/                    # 技术文档
│   ├── technical.zh-CN.md    # 中文
│   └── technical.en.md       # English
├── LICENSE
├── README.md
└── README.en.md
```
