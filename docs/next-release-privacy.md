# 下一版本：剪贴板隐私与防误覆写优化规划

更新日期：2026-11-27。

状态：已完成并集成验证。

## 范围收敛说明

结合 [README.md](../README.md) 与 [technical.zh-CN.md](technical.zh-CN.md) 已明确的可信局域网使用前提，原待办中的三项已精简为以下唯一高价值项：
- **不推进局域网 WSS/TLS 证书链与 PAKE（原第 1 项）**：产品定位为家庭/可信局域网及虚拟组网直连，现有 `HMAC-SHA256(secret, nonce)` 挑战-响应与配对码锁定已覆盖未授权连接防护，不承担公网或公共 Wi-Fi 对抗场景。
- **取消 Android Keystore 配对密钥加密（原第 3 项）**：Android 应用私有存储本身受系统沙箱隔离，Keystore 在跨 ROM 升级或锁屏变更时反而易造成用户无故掉配对；若需防云同步仅需保留备份排除规则即可。
- **保留并聚焦：剪贴板隐私标记与防竞态恢复（原第 2 项精简版）**，只保留对日常手感与历史整洁度真正有用的改动，不做图片/富文本全格式备份。

## 制作顺序与详细技术方案

### 阶段 1：Windows 剪贴板历史与云同步隔离标记（防 `Win+V` 污染）

- **目标文件**：`desktop/crates/agentpad-input/src/win.rs`（`inject_text`）
- **现状问题**：当前通过 `arboard::Clipboard::set_text` 写入文本后注入 `Ctrl+V`，系统会把每次发出的语音或长文本写进 Windows `Win+V` 剪贴板历史，并可能触发微软跨设备云剪贴板同步。
- **实现方案**：
  1. 封装 Win32 原生剪贴板写入事务（`OpenClipboard` → `EmptyClipboard` → `SetClipboardData` → `CloseClipboard`），写入 `CF_UNICODETEXT` 的同时在同一事务内注册并写入以下标准剪贴板格式：
     - `ExcludeClipboardContentFromMonitorProcessing`（4 字节非零 `DWORD`）
     - `CanIncludeInClipboardHistory`（4 字节 `DWORD`，值为 `0`）
     - `CanUploadToCloudClipboard`（4 字节 `DWORD`，值为 `0`）
  2. 原纯文本存在、粘贴完成后恢复旧文本时，同样带历史排除标记写回，避免旧文本在 `Win+V` 中重复置顶。
- **预期效果**：手机端高频发送语音或提示词时，不再刷屏污染用户的 `Win+V` 剪贴板历史与云端剪贴板。

### 阶段 2：Windows 恢复前序列号校验（防竞态误删用户新复制内容）

- **目标文件**：`desktop/crates/agentpad-input/src/win.rs`（`inject_text`）
- **现状问题**：当前固定等待 `80ms` 后直接把 `old` 写回剪贴板（若原剪贴板无纯文本则不处理，导致临时发送文本残留）。如果用户在这 `80ms` 内刚好在电脑上复制了新内容，恢复动作会把新内容覆盖掉。
- **实现方案**：
  1. 写入发送文本前，读取原有纯文本 `old_text: Option<String>`（若原内容非文本或为空则记为 `None`）。
  2. 写入本次临时文本并关闭剪贴板后，立即调用 `GetClipboardSequenceNumber()` 记录 `seq_after_set`。
  3. 注入 `Ctrl+V` 并等待 `80ms` 后，再次调用 `GetClipboardSequenceNumber()`：
     - 若序列号 **仍等于 `seq_after_set`**：说明期间没有任何其他程序或用户改动剪贴板。此时若 `old_text` 为 `Some(prev)` 则恢复 `prev`（带排除标记）；若为 `None`（原本为空或非文本）则调用 `EmptyClipboard()` 清理本次留下的临时发送文本。
     - 若序列号 **已发生变化**：说明用户或系统刚刚复制了新内容，直接放弃清理/恢复，100% 保留新内容。

### 阶段 3：macOS 补齐旧文本恢复与 Transient 临时标记

- **目标文件**：`desktop/crates/agentpad-input/src/macos.rs`（`inject_text`）
- **现状问题**：当前 `macos.rs` 直接 `cb.set_text(&text)` 后注入 `Cmd+V`，既没有保存/恢复原文本，也没有屏蔽剪贴板历史工具（Alfred、Raycast、Paste、Maccy 等）和 Universal Clipboard 跨设备接力。
- **实现方案**：
  1. 写入前从 `NSPasteboard::generalPasteboard` 读取原有纯文本 `old_text: Option<String>`。
  2. 在 `declareTypes` / `clearContents` 写入临时文本时，同步附加以下粘贴板类型与状态：
     - `org.nspasteboard.TransientType`
     - `org.nspasteboard.AutoGeneratedType`
     - 通过 `NSPasteboard` `prepareForNewContentsWithOptions:` 设置 `NSPasteboardContentsCurrentHostOnly`（阻止通用剪贴板同步到同一 Apple ID 下的手机或平板）。
  3. 记录写入后的 `changeCount`；注入 `Cmd+V` 并等待 `80ms` 后，若 `changeCount` 未被其他程序改变：
     - 有 `old_text` 则带同样 `TransientType` / `CurrentHostOnly` 写回旧文本；
     - 无 `old_text` 则清空当前临时发送文本。

## 验收标准

1. **Windows 端**：连续从手机发送 10 条文字后打开 `Win+V`，历史中不出现发送文本；发送前后原剪贴板有文字时正确恢复且不破坏 `Win+V` 顺序；原剪贴板为空时发送结束后不残留发送文本；若用户在粘贴瞬间复制了新文字，新文字不被覆盖。
2. **macOS 端**：发完文字后原有复制文本自动恢复；Alfred / Raycast / Maccy 等历史工具不记录本次临时文本，且同账号旁边的 iPhone / iPad 不会收到接力剪贴板弹窗。
3. **边界回归**：上述改动不延长「自动回车」的 80ms 节奏，也不引入图片/富文本全格式读取，避免影响中文长文本实时上屏响应速度。
