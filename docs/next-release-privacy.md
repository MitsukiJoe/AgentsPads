# 下一版本：隐私改进待办

记录日期：2026-11-06。

状态：推迟到下一版本。本次只记录方案，没有实现下列改动。当前安装、权限切换和更新流程的验收，不等于以下隐私改进已经完成。

## 1. 通信加密与可信配对

- [ ] 日常连接改为标准 WSS/TLS，在发送配对凭证或控制输入之前验证对端身份；不能接受任意证书，也不能直接信任首次从网络拿到的证书。
- [ ] 扫码时绑定电脑的长期公钥身份及一次性配对凭证。身份按设备和权限模式保存，不只按 IP 保存，保持换网、换 IP 和自动重连体验。
- [ ] 手机、Windows、macOS，以及 Android 的原生和备用连接通道一起升级。协议不兼容时明确提示更新，不自动退回明文连接。
- [ ] 普通与管理员身份继续隔离；正常程序更新和失败回滚保留身份，主动重置或身份丢失时要求重新配对。

待决定：手动配对继续使用短码，还是改用较长的随机配对串。保留四位码需要选用并验证适合跨端的 PAKE 安全配对实现，将结果绑定实际加密连接；不能直接把四位码作为加密密钥。长配对串的实现复杂度较低，扫码体验可以保持不变。尚未决定删除或改变现有短码入口。

验收应覆盖错误身份、伪装对端、连接被篡改、重放及明文降级拒绝，并验证换网、休眠恢复、两种权限、自动重连和输入延迟。

参考：[Syncthing 的 TLS 与设备身份校验](https://docs.syncthing.net/users/security.html)、[Android 无线 ADB 配对架构](https://android.googlesource.com/platform/packages/modules/adb/+/HEAD/docs/dev/adb_wifi.md)。

## 2. 剪贴板隐私与安全收尾

当前 Windows 实现是写入文字、发送粘贴快捷键、等待 80 毫秒，再在存在旧纯文本时尝试恢复；无旧文本或提前失败时可能留下新内容。macOS 当前没有恢复或清空。因此不能描述为“每次贴完即删除”。

- [ ] 保留整段粘贴方式。Windows 默认为本次临时内容设置不进入系统剪贴板历史、不跨设备同步的标记，优先使用现有 arboard 支持的接口。
- [ ] 恢复或清理前核对剪贴板仍属于本次操作，在检查与修改之间防止竞态；用户期间复制的新内容不得被覆盖或删除。
- [ ] 成功和失败路径都执行受保护的收尾。考虑原剪贴板为空、图片、富文本和无法完整备份的格式，明确无法恢复时的处理方式，不假称只恢复纯文本就能完整保留原内容。
- [ ] 不依靠缩短固定等待时间保证隐私。快捷键发送成功不代表目标程序已经读取文字，清理时机需要在实际目标软件中验证。
- [ ] macOS 单独使用禁止跨设备同步及临时、敏感内容标记，验证系统历史和支持这些标记的剪贴板工具的实际行为。

边界：不修改用户全局剪贴板设置、不清空用户已有历史。恢复当前内容不能撤回过去保存的副本；隐私标记也不能阻止所有本机程序读取正在使用的剪贴板。过去回滚的输入实验不作为当前已实现功能。

验收应覆盖空剪贴板、旧文字、图片与富文本、发送失败、连续发送、用户中途复制，以及历史、跨设备同步和常用目标软件的粘贴完整性。

参考：[Windows 剪贴板历史与云同步控制](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats)、[Apple currentHostOnly](https://developer.apple.com/documentation/appkit/nspasteboard/contentsoptions/currenthostonly)。

## 3. Android 配对密钥加密存储

- [ ] 通过已有 Kotlin 桥接使用 Android Keystore 保护加密钥匙，以系统 AES-GCM 加密配对密钥，密文保存在应用私有且排除备份的位置；普通设置继续使用原有存储。
- [ ] 保持自动重连，不要求每次使用时进行指纹或密码验证，也不强制依赖特定安全硬件。存储操作不进入鼠标高频发送路径，不阻塞主线程。
- [ ] 迁移顺序为读取旧数据、加密保存、读回解密核对、最后删除旧明文字段。所有保存路径都要调整，避免保存其他设置时重新写回明文。
- [ ] 迁移中断可重试，失败不自动降级为明文。系统钥匙失效、重装或换手机后明确提示重新配对，不静默清空设备列表掩盖错误。
- [ ] 配对密钥继续排除备份、设备迁移和诊断日志。需要作废历史明文副本时轮换对应电脑身份的配对密钥，再重新配对；删除当前字段不等于安全擦除历史备份。

边界：Keystore 保护加密用的钥匙，解密后的配对密钥仍会在应用运行时进入内存；不承诺设备或应用进程被完全控制后仍能保密。

验收应覆盖现有配对信息迁移、迁移中断重试、再次保存设置、自动重连、密钥失效和重新配对，确认没有恢复明文保存或无提示丢失数据。

参考：[Android Keystore](https://developer.android.com/privacy-and-security/keystore)、[Android 备份排除规则](https://developer.android.com/identity/data/autobackup)。
